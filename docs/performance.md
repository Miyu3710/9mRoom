# 性能基线（T19）

## 环境

- Windows 11，125% 缩放，2560×1440
- AMD Ryzen 7 9700X（8 核 / 16 逻辑处理器）
- .NET 8，Debug 构建，WPF 客户端 + ASP.NET Core 服务端
- 叠加层开启，房间 1 人，媒体播放中

## 方法

1. 启动客户端与服务端，等待 15 秒预热。
2. 读取进程 `TotalProcessorTime` 与 `WorkingSet64`，等待 60 秒后再次读取。
3. 单核占用 = ΔCPU / 60 × 100%；任务管理器口径 = 单核占用 / 16。
4. 同时记录服务端数据。

## 结果

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 客户端单核 CPU | 8.98% | 0.78% |
| 客户端任务管理器 CPU | 0.56% | 0.05% |
| 客户端工作集 | 236.6 → 241.5 MB | 219.1 → 225.2 MB |
| 服务端单核 CPU | 0.16% | 0.00% |
| 服务端工作集 | 62.7 MB | 62.3 MB |

均满足“平均 CPU < 1%”（按任务管理器口径）。内存约 225 MB（Debug 构建，Release 预计更低）。

## 降频策略

| 状态 | presence 间隔 | 每分钟发送 |
| --- | --- | --- |
| 专注（活跃） | 3 秒 | 20 |
| 自动空闲 ≥ 5 分钟 | 15 秒 | 4 |
| 隐身 | 30 秒 | 2 |
| 暂停上报 | 不发送 | 0 |

隐身时仍保留 30 秒心跳以维持在线/隐身状态，但 payload 不含状态块、标题与今日时长。

## 本次优化

- 界面刷新从固定 1 秒改为：计时器运行时 1 秒，空闲时 2 秒。
- 专注统计的历史列表从每秒重建改为每分钟重建，其余时间只刷新文本。
- presence 发送间隔按状态自适应。
